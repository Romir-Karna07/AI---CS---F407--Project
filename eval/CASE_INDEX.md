# Case index

Generated by `python eval/build_case_index.py`. Case file stem = what the case is (`<group>_<nn>_<layout / language / failure mode>`); the reference with the expected output is in the `reference` folder of the same set (`reference/<case_id>.json`). `must fail` = the correct outcome is a clean failure that stores nothing.

## Do the sets share data?

Nothing here is used to train a model: the pipeline is rule-based plus a hosted model that is never fine-tuned. "Used twice" can therefore only mean (a) the same records in the cases the code was developed on (dev) and in the cases it is scored on (official), which would be leakage, or (b) the same records scored twice. Computed now from the references (record = agent, place, period, crop, entity) and from the file bytes:

| set A | set B | records A | records B | shared records | identical files |
|---|---|---|---|---|---|
| official | official AI | 893 | 236 | 232 | 0 |
| official | dev | 893 | 946 | 0 | 0 |
| official | dev AI | 893 | 249 | 0 | 0 |
| official AI | dev | 236 | 946 | 0 | 0 |
| official AI | dev AI | 236 | 249 | 0 | 0 |
| dev | dev AI | 946 | 249 | 103 | 0 |

* **Development vs scoring: no shared record and no shared file** (dev / dev AI are built from the dev districts, official / official AI from the held-out districts Imphal West, Thoubal, Ukhrul). The `dev` and `official` folders look alike because each official case has a *twin* in the same layout, built from different districts: the layout repeats, the data does not. `eval/contamination_check.py` enforces this on every run.
* **Official vs official AI** (and dev vs dev AI) **do share records**: the held-out records are few, so the AI cases re-use them in layouts the rule-based reader cannot take (a title above the header, Tamil headers, an image ...). Both sets are only scored, not developed on (code changes made after seeing their results are disclosed in eval/README.md), and they are reported separately (`eval/phase2_metrics.csv` vs `eval/ai/ai_metrics.csv`), so no number counts a record twice. Within one set, the PDF cases also re-use the records of the CSV / JSON cases in a PDF layout (the document agent is scored on its own).
* Rainfall records of the IMD and NASA POWER sources share the key (place, month) but are different values from different sources.
